# Как устроена учебная сессия

## Главная цепочка

```text
Supabase
↕
services
↕
study.store
↕
StudySession
↕
Flashcard
```

Данные идут сверху вниз: от Supabase к карточке. Действия пользователя идут снизу вверх: от кнопки к Supabase.

## Ответственность слоёв

### Supabase

Постоянно хранит пользователей, слова, переводы и прогресс. Данные не исчезают после обновления страницы.

### Services

Работают только с Supabase:

- `dictionary.service.ts` загружает слова;
- `progress.service.ts` сохраняет ответы и рассчитывает прогресс;
- `auth.service.ts` работает с авторизацией.

Сервис не отображает интерфейс и не хранит состояние React.

### Store

Хранит состояние текущей учебной сессии:

- загруженные слова;
- индекс текущего слова;
- загрузку и ошибку;
- действия загрузки слов и сохранения ответа.

Стор связывает компоненты и сервисы. Он вызывает сервис, ждёт результат и обновляет состояние.

В Zustand:

- `get()` читает актуальное состояние;
- `set(...)` изменяет состояние и запускает перерисовку подписанных компонентов.

### StudySession

Связывает стор с интерфейсом:

- запускает загрузку слов;
- получает состояние из стора;
- выбирает `words[currentIndex]`;
- подготавливает переводы;
- показывает загрузку, ошибку или карточку;
- передаёт ответы пользователя обратно в стор.

Правильный порядок проверок:

```text
1. isLoading
2. error
3. currentWord
4. подготовка translation
5. Flashcard
```

### Flashcard

Только отображает одну карточку и сообщает о действиях пользователя через пропсы:

- `onKnow`;
- `onUnknown`.

Она не обращается к Supabase и не импортирует сервисы. Локальный `useState` хранит только визуальное состояние переворота.

## Загрузка слов

```text
StudySession вызывает loadWords
→ store включает isLoading
→ dictionary.service запрашивает Supabase
→ store сохраняет words
→ Zustand уведомляет StudySession
→ React показывает текущую карточку
```

`await` приостанавливает только текущую асинхронную функцию, а не всё приложение.

`void loadWords(...)` запускает Promise, но не использует его результат в компоненте. Результат приходит через обновление стора.

## Сохранение ответа

```text
Кнопка вызывает onKnow/onUnknown
→ StudySession вызывает submitAnswer
→ store через get() находит текущее слово
→ progress.service сохраняет ответ
→ store увеличивает currentIndex
→ React показывает следующую карточку
```

Индекс увеличивается только после успешного `await answerWord(...)`. При ошибке пользователь остаётся на текущей карточке.

`key={currentWord.id}` пересоздаёт `Flashcard` при смене слова и сбрасывает её переворот.

## Обработка ошибок

Асинхронные операции оформляются так:

```text
до try: включить загрузку и очистить старую ошибку
try: выполнить запрос и сохранить успешный результат
catch: сохранить сообщение ошибки
finally: обязательно выключить загрузку
```

В `try` помещается операция, которая может завершиться ошибкой, и код, зависящий от её успешного результата.

## Где хранить состояние

- Supabase — постоянные данные.
- Store — общее состояние учебной сессии.
- Локальный `useState` — состояние, нужное только одному компоненту.
- Props — данные и события между родительским и дочерним компонентами.

## Главное правило

Компонент отображает и сообщает о действии. Стор управляет сценарием. Сервис общается с внешней системой.
